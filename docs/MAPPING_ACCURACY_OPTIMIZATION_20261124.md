- **업무 오추천.** Final Concept의 원시 응답에서 일반적인 표준 역할 혼동 18건, 거래일과 월수요 기간 또는 다른 필드의 혼동 17건, 잘못된 문서 유형 17건, 거래처 코드 12건, 의미 근거 부족 12건이었다. 제품·자재·구성품, 현재고·가용재고, BOM 산출량·투입량, 발주·반품·생산실적·수량 대신 금액도 분리 집계했다. 동일 열의 중복 대상과 의미 오류를 함께 세는 통계 외에, 계약·중복·의미/HOLD 순으로 최초 실패를 분류했다. 원시 후보 한 개만 반환한 모드에서는 검색 Top-3 실패를 관측할 수 없다.
- **계약 오류.** Concept은 Final 34/130문서, Confirmatory 20/100문서에서 영향을 받았다. 중복 대상 행 수는 각각 102/54다. 예시로 두 열을 같은 표준 필드로 제시하면 둘 다 보류했다. ID 누락·중복, 허용 필드 위반, JSON 형태·종료 오류는 별도 카운터로 남겼다. 문서 전체에 문제가 생겨도 검증된 개별 후보의 집계는 유지했다.
- **후처리의 영향.** Phase 3→4 Final 오추천은 5건 제거·3건 추가로 순 2건 감소했다. Confirmatory에서는 2건 제거·1건 추가였다. Phase 5 중복 후보만 다시 비교한 보수적 국소 전략은 두 패널 모두 추가 채택이 0건이었다. 중복 중 정답 후보가 존재하더라도 독립적인 역할 증거의 차이가 충분치 않았다.

## 프로파일과 업무 개념

`phase5-cell-evidence-v1`은 셀 원문과 표시 형식, 검증 가능한 원시 자료형, 가능한 변환 형식을 구분한다. 쉼표 천 단위, 숫자 문자열, 선행 0, 고정 자릿수 Excel 코드, 날짜와 연월, 정수·소수, 음수 괄호, 통화·백분율, 결측·혼합·단위를 집계한다. 인식 가능한 외국식 구분자와 등록되지 않은 단위는 확인 대상으로 둔다. 통상적인 숫자 텍스트와 Excel의 코드 표시 형식은 원문을 유지한다.

원본의 변환 불가·단위·정수·충돌은 Hard 조건으로 사용한다. 값의 종류·일부 파싱 가능성·통계와 역할 유사도는 Soft 증거로 사용한다. 실제 수요 파서가 지원하는 한글 연월이나 월초 날짜는 월간 역할 근거가 있을 때 추천할 수 있다. 주문·거래 이벤트의 일자는 월초로 표시되어도 집계·업무 변환 대상으로 보류한다. 등록 단위처럼 프로파일에 노출된 정책 확인 표기는 Hard 조건까지 넘기지 않는다.

`manufacturing-research-v2`는 업무 영역 → 표준 역할 → 문서 유형·허용 형식·구분 증거를 정의한다. 별도의 조달·반품·생산실적·거래처·금액·거래 이벤트 개념은 직접 매핑에서 제외한다. `mapping-research-contrast-v1`의 프롬프트와 열 ID enum 응답은 기존 공유 계약과 연구 전용 지식에 연결했다. 의미 판별은 헤더와 주변 문서 단서를 쓰고 자료형 검증은 원본 셀을 독립적으로 확인한다.

## 범위 탐지와 반복 양식

구조 정답과 SHA가 확인된 기존 분류기 합성 XLSX 14개·30표만 대상으로 범위를 비교했다. 기존 파서 1/30에서 독립 밀도 방식 19/30으로 정확 범위가 늘었다. 스타일 추가도 19/30이었고 다중 헤더 깊이는 2/2를 맞혔다. IoU≥0.5 기준 스타일 방식은 정밀도 20/25, 재현율 20/30, 정답 전체 기준 평균 IoU 0.666이었다. 정확 범위의 원본 데이터 캐시 셀 1,907개가 정답과 일치했다. 스타일을 사용한 후보도 14문서 중 4개는 범위 확인이 필요하다. 분류기 파일 200개 전체 점수나 수동 범위 선택 성공률로 해석할 수 없다. ## 운영 검토와 재현
