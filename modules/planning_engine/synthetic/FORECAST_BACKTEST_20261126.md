# 충파모 합성 데이터 수요예측 백테스트 (2026-11-26)

> 작성 이희원, 2026-11-26 (KST). 기준 `main` `3a45033`. 데이터 `CHUNGPAMO-2027`(SYNTHETIC).
> 재현: `generate.py` → `forecast_request.py`로 `data/forecast/request.json`을 만든 뒤(README §1 순서), `modules/planning_engine`에서 `PYTHONUTF8=1 python -m synthetic.forecast_backtest` (약 20초). 스크립트 [forecast_backtest.py](forecast_backtest.py).
> 원자료 출력: `data/forecast/backtest_20261126.json`(요약 + 예측 행 전부). `synthetic/data/`는 git 제외라 각자 PC에서 다시 만든다.

## 1. 왜 했나

P50 = MA12, P80·P90 = LightGBM 분위수라는 결정은 Kaggle 공개 데이터(상위 100제품, 2012~2016)로 내렸다(`docs/26-10-26_수요예측데이터·실험기록.md` §7~9, 저장소 밖). 같은 절차를 팀 데모 데이터에도 돌려 결과가 같은지 확인한다.

## 2. 방법 — Kaggle 실험과 같게

| 항목 | 내용 |
|---|---|
| 데이터 | `data/forecast/request.json`의 승인 월 수요. 9제품, 2022-01~2026-12 (CP-ON3-3030은 2025-07 출시) |
| 예측기 | **실제 엔진 `engine.forecast.run` 그대로**. 기준 월마다 그 달까지의 실적만으로 다시 학습 |
| 비교 대상 | P50: `MA12`(배포 기본) vs `LGBM_L1`. 기준선 ma6·ma3·snaive·naive. P80·P90: 배포 설정(MA12 실행)의 분위수 |
| 분할 | 목표 월 **2025 = 검증**, **2026 = 테스트** (rolling-origin). 주 지표 **h=2**, h=1·3 보조 |
| 지표 | WAPE(오차 합 ÷ 실제 합), Bias%(+ 과대 / − 과소), P80·P90 커버리지(실제 ≤ 예측 비율), pinball(÷ 실제 합) |
| 채택 규칙 (사전) | 검증 h=2에서 MA12 대비 WAPE **5% 이상 개선** 그리고 \|Bias\| ≤ 5% |
| 평가 행 | 엔진이 예측을 낸 (제품, 목표 월, h)만. 검증 h=2 96행(8제품 × 12), 테스트 h=2 101행 |

## 3. 결과

### 3.1 P50 (h=2)

| 모델 | 검증 WAPE | 검증 Bias | 테스트 WAPE | 테스트 Bias |
|---|---|---|---|---|
| **MA12** (배포) | 0.0723 | +0.1% | 0.0770 | −2.9% |
| **LightGBM** | **0.0644** | −1.0% | 0.0768 | −3.1% |
| ma6 | 0.0717 | +0.1% | **0.0751** | −2.0% |
| ma3 | 0.0710 | +0.1% | 0.0797 | −1.3% |
| snaive | 0.0781 | +0.3% | 0.1024 | −3.9% |
| naive | 0.0933 | +0.3% | 0.1036 | −0.6% |

h=1·3도 검증에서는 LightGBM이 앞선다(h1 0.0598 vs 0.0720, h3 0.0647 vs 0.0735). 테스트에서는 h1 LightGBM이 나쁘고(0.0826 vs 0.0774), h3는 앞선다(0.0752 vs 0.0794).

**채택 규칙 판정: 형식상 통과.** 검증 개선 10.9%, Bias −1.0%. Kaggle에서는 −1.3%(동급)로 통과하지 못했다.

### 3.2 그런데 차이는 거의 전부 선물세트 한 제품에서 나온다

| 범위 (h=2) | 검증 MA12 | 검증 LightGBM | 테스트 MA12 | 테스트 LightGBM |
|---|---|---|---|---|
| 9제품 전체 | 0.0723 | 0.0644 (**+10.9%**) | 0.0770 | 0.0768 (+0.3%) |
| **CP-GIFT-12 제외** | 0.0568 | 0.0569 (**−0.1%**) | 0.0629 | 0.0678 (**−7.8%**) |

선물세트를 빼면 검증에서는 같고, 테스트에서는 MA12가 낫다. h=1·3도 마찬가지다(제외 시 검증 +7.8% / +1.4%, 테스트 −19.1% / −1.5%).

**CP-GIFT-12에서 일어난 일** (평소 월 200개, 설·추석 달만 약 2,000개. 명절 달은 해마다 바뀜)

| 목표 월 | 실제 | MA12 | LightGBM |
|---|---|---|---|
| 2025-01 (설) | 2,000 | 492 | 499 |
| 2025-02 | 200 | 493 | 195 |
| 2025-09 (추석) | 1,910 | 498 | 487 |
| 2026-02 (설) | 1,890 | 497 | 201 |
| 2026-09 (추석) | 2,040 | 488 | 499 |
| 그 외 달 | 190~220 | 약 490 | 약 200 |

- **MA12**는 명절 2번을 평균에 섞어 비수기를 **약 2.5배 과대예측**한다(WAPE 검증 0.98).
- **LightGBM**은 비수기를 맞히지만(약 200) **명절 달은 둘 다 못 맞힌다**. 명절 날짜가 해마다 1·2월, 9·10월로 움직이는데, 피처에는 명절 정보가 없다(작년 같은 달만 있음).
- 그래서 LightGBM이 앞선 이유는 "명절을 예측해서"가 아니라 "비수기를 덜 틀려서"다.

### 3.3 제품별 (h=2 WAPE, 검증 → 테스트)

| 제품 | 특성(합성 설계) | MA12 | LightGBM |
|---|---|---|---|
| CP-N3-3030 | 주력, 할인 행사 달 | 0.052 → 0.042 | 0.059 → 0.058 |
| CP-N3-2730 | 주력 | 0.045 → 0.069 | 0.048 → 0.070 |
| CP-N3-2524 | 안정 | 0.064 → 0.060 | 0.060 → 0.064 |
| CP-N2-3030 | 감소 추세 −0.6%/월 | 0.065 → 0.063 | 0.063 → 0.058 |
| CP-R2-3030 | 안정 | 0.048 → 0.055 | 0.039 → 0.053 |
| CP-P4-2524 | 성장 +1.2%/월 | 0.081 → 0.082 | **0.065 → 0.055** |
| CP-B2-JUMBO | 들쭉날쭉 | 0.111 → 0.115 | 0.116 → 0.121 |
| CP-GIFT-12 | 명절 10배 | 0.981 → 0.963 | **0.507 → 0.641** |
| CP-ON3-3030 | 2025-07 출시, 증가 중 | – → 0.163 (5행) | – → 0.218 |

추세가 뚜렷한 제품(P4)은 LightGBM이 낫고, 주력·안정 제품은 MA12가 같거나 낫다.

### 3.4 P80·P90 (LightGBM 분위수, 배포 설정)

| 구간 | P80 커버리지 (목표 0.80) | P90 커버리지 (목표 0.90) | pinball 0.8 / 0.9 |
|---|---|---|---|
| 검증 h=1 / 2 / 3 | 0.81 / 0.77 / 0.81 | 0.92 / 0.89 / 0.92 | h2: 0.034 / 0.023 |
| 테스트 h=1 / 2 / 3 | **0.71 / 0.71 / 0.71** | **0.82 / 0.80 / 0.83** | h2: 0.045 / 0.032 |

- 검증(2025)은 목표에 맞다. **테스트(2026)는 P80 0.71, P90 0.80으로 목표보다 낮다.** 2026년 실적이 예측보다 약 3% 높았기 때문이다(테스트 Bias −3%: 성장 제품 P4, 출시 제품 ON3).
- 즉 2026 같은 해에는 P80이 "10번 중 8번"이 아니라 "10번 중 7번" 정도만 버틴다. 안정형 계획의 실제 대비 수준이 이름보다 낮을 수 있다.
- 11/15 확인(`README.md` §1, 2026년 P80 적중률 약 71%)과 같은 결과다.

## 4. 결론과 제안

**P50 기본값은 MA12를 유지한다(엔진 변경 없음).** 규칙은 형식상 통과했지만:

1. 개선이 **한 제품(명절 선물세트)** 에서만 나오고, 그 제품도 명절 달은 둘 다 못 맞힌다. 나머지 8제품은 검증 동급, 테스트에서 MA12가 7.8% 낫다.
2. **테스트에서 확인되지 않는다**(전체 +0.3%).
3. 이 데이터는 **우리가 규칙을 넣어 만든 합성 데이터**이고 표본이 작다(검증 96행). 모델 선택 근거로 쓰면 우리가 넣은 규칙을 맞히는 모델을 고르게 된다. 모델 선택은 실제 주문 이력(Kaggle) 결과를 유지하고, 실기업 데이터가 들어오면 같은 스크립트로 다시 비교한다.

**기록해 둘 개선 후보** (결정 아님, 멘토·팀 논의용)

| 문제 | 영향 | 후보 |
|---|---|---|
| 명절 제품: MA12가 비수기 2.5배 과대, 두 방식 모두 명절 달 놓침 | 선물세트 계획·자재(MP-GIFTBOX) 과다 또는 명절 결품 | 명절 달력 피처 추가, 계절 제품만 별도 방식, 또는 담당자 보정(현재 README §1의 방침) |
| 성장 제품: MA12가 늦게 따라감, P80 커버리지 0.71 | 안정형이 생각보다 덜 넉넉함 | 추세 제품 표시, 분위수 보정(과거 커버리지로 폭 조정) 검토 |
